## この記事について

[The Rust Programming Language](https://doc.rust-lang.org/book/)（the Book）を、手を動かして進めるシリーズの 2 本目です。[1 本目](/ja/blog/rust-book-guessing-game)では、mise で Rust を入れて、2 章の数当てゲームまで作りました。

今回は [3 章「よく使うプログラミングの概念」](https://doc.rust-lang.org/book/ch03-00-common-programming-concepts.html)です。変数、データ型、関数、コメント、制御フローと、どの言語にもある話ですが、Rust ならではのところがたくさんあります。前回と同じく、Book のとおりに動かした結果と、わざと書き換えたときのコンパイラのエラーを載せます。普段 TypeScript を書いている目線で、違うところを比べていきます。

試した環境は前回と同じで、Rust 1.99.1、Windows 11 の PowerShell です。節ごとに `cargo new` でプロジェクトを作っています。


## 変数と可変性（3.1 節）

### 2 回目の代入はできない

[3.1 節](https://doc.rust-lang.org/book/ch03-01-variables-and-mutability.html)は、前回も出てきた「変数は既定で変更できない」の話から始まります。`let` で作った変数に、もう一度代入してみます。

```rust title="src/main.rs"
fn main() {
    let x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}
```

```console
❯ cargo run
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
error[E0384]: cannot assign twice to immutable variable `x`
 --> src\main.rs:4:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     println!("The value of x is: {x}");
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++

For more information about this error, try `rustc --explain E0384`.
error: could not compile `variables` (bin "variables") due to 1 previous error
```

前回の `E0596` は「変更できる形で借りられない」でしたが、今回は `E0384`「変更できない変数に 2 回代入した」です。どちらも直し方は `mut` を付けることで、コンパイラは `+++` で付ける位置まで示してくれます。

TypeScript と並べると、こうなります。

| やりたいこと | TypeScript | Rust |
| --- | --- | --- |
| 後から変えない変数 | `const x = 5` | `let x = 5` |
| 後から変える変数 | `let x = 5` | `let mut x = 5` |
| コンパイル時に決まる定数 | （専用の仕組みは無い） | `const X: i32 = 5` |

同じ `let` でも、TypeScript では「変えられる」、Rust では「変えられない」なので、最初は混乱します。

### 定数には型が要る

Rust の `const` は、TypeScript の `const` とは別物です。`let` と違って、型を必ず書きます。書かないとどうなるか試します。

```rust title="src/main.rs"
const MAX_POINTS = 100_000;

fn main() {
    println!("{MAX_POINTS}");
}
```

```console
❯ cargo build
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
error: missing type for `const` item
 --> src\main.rs:1:17
  |
1 | const MAX_POINTS = 100_000;
  |                 ^ help: provide a type for the constant: `: i32`

error: could not compile `variables` (bin "variables") due to 1 previous error
```

「型を書け、たとえば `: i32`」と言われました。`100_000` の `_` は、桁を読みやすくするための区切りで、値は 100000 です。

もう 1 つの違いは、定数の値はコンパイルのときに決まっていないといけないことです。実行してみないと分からない値を入れてみます。

```rust title="src/main.rs"
fn main() {
```

「定数の中で、定数でない値を使おうとした。`let` にしたらどうか」というエラーです。TypeScript の `const` は、実行時の値でも何でも入れられるので、ここが大きく違います。Rust の `const` は、プログラムに埋め込まれる「名前の付いた値」だと思うと分かりやすいです。

### シャドーイング

Rust では、同じ名前の変数を `let` で何度でも作り直せます。これをシャドーイング（影で隠す）と呼びます。

```rust title="src/main.rs"
fn main() {
    let x = 5;
    let x = x + 1;
    {
        let x = x * 2;
        println!("inner x: {x}");
    }
    println!("outer x: {x}");
}
```

```console
❯ cargo run
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.72s
     Running `target\debug\variables.exe`
inner x: 12
outer x: 6
```

`x` は 5 で作られ、6 に作り直されて、`{}` の中では 12 になります。`{}` を抜けると中の `x` は消えて、外の 6 に戻りました。`mut` で値を書き換えたのではなく、新しい変数を同じ名前で作っています。

JavaScript で同じスコープに `let` を 2 回書くと、そもそも実行できません。

```console
❯ bun -e 'let x = 5; let x = 6;'
1 | let x = 5; let x = 6;
                   ^
error: "x" has already been declared
    at C:\Users\Jam\rust-demo\work\[eval]:1:16

1 | let x = 5; let x = 6;
        ^
note: "x" was originally declared here
   at C:\Users\Jam\rust-demo\work\[eval]:1:5

Bun v1.4.2 (Windows x64)
```

シャドーイングが便利なのは、型を変えられるところです。文字列の空白を、その個数に置き換えてみます。

```rust title="src/main.rs"
fn main() {
    let spaces = "   ";
    let spaces = spaces.len();
    println!("{spaces}");
}
```

```console
❯ cargo run
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.54s
     Running `target\debug\variables.exe`
3
```

`let mut` にして、代入で同じことをしようとするとエラーになります。

```rust title="src/main.rs"
fn main() {
    let mut spaces = "   ";
    spaces = spaces.len();
    println!("{spaces}");
}
```

```console
❯ cargo build
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
error[E0308]: mismatched types
 --> src\main.rs:3:14
  |
2 |     let mut spaces = "   ";
  |                      ----- expected due to this value
3 |     spaces = spaces.len();
  |              ^^^^^^^^^^^^ expected `&str`, found `usize`

For more information about this error, try `rustc --explain E0308`.
error: could not compile `variables` (bin "variables") due to 1 previous error
```

`mut` は「値を変えられる」であって、「型を変えられる」ではありません。`spaces` は最初の値で文字列（`&str`）と決まったので、数（`usize`）は入れられません。前回の数当てゲームで `let guess: u32 = guess.trim().parse()...` と同じ名前で作り直したのも、このシャドーイングです。`guess_str` と `guess_num` のように名前を分けなくて済みます。

## データ型（3.2 節）

[3.2 節](https://doc.rust-lang.org/book/ch03-02-data-types.html)は型の話です。Rust は静的な型の言語で、コンパイルのときにすべての変数の型が決まっていないといけません。ほとんどは推論してくれますが、推論できないときは型を書けと言われます。前回も見た `parse()` が、その例です。

```rust title="src/main.rs"
fn main() {
```

### 整数の型

JavaScript の数は、基本的に `number` の 1 種類だけです。Rust には、大きさと符号で分かれた整数の型がたくさんあります。

| 大きさ | 符号あり | 符号なし |
| --- | --- | --- |
| 8 ビット | `i8` | `u8` |
| 16 ビット | `i16` | `u16` |
| 32 ビット | `i32` | `u32` |
| 64 ビット | `i64` | `u64` |
| 128 ビット | `i128` | `u128` |
| マシンに合わせる | `isize` | `usize` |

`i` が符号あり（マイナスも入る）、`u` が符号なし（0 以上だけ）です。型を書かずに整数を書くと `i32` になります。`usize` は、配列の添字や長さに使う型で、さっきの `spaces.len()` が返したのもこれです。

### 整数のオーバーフロー

![u8 の実行時オーバーフローは既定の debug ビルドでは panic し、release ビルドでは 0 に回り込む。コンパイル時に分かるオーバーフローはエラーになる](/rust/integer-overflow.avif)

型ごとに入る範囲が決まっているので、範囲を超えたらどうなるかが気になります。`u8` は 0 から 255 までです。まずは素直に `255 + 1` と書いてみます。

```rust title="src/main.rs"
fn main() {
    let x: u8 = 255 + 1;
    println!("{x}");
}
```

```console
❯ cargo build
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
error: this arithmetic operation will overflow
 --> src\main.rs:2:17
  |
2 |     let x: u8 = 255 + 1;
  |                 ^^^^^^^ attempt to compute `u8::MAX + 1_u8`, which would overflow
  |
  = note: `#[deny(arithmetic_overflow)]` on by default

error: could not compile `data_types` (bin "data_types") due to 1 previous error
```

値がコンパイルのときに分かっているので、コンパイラが見つけて止めてくれました。では、実行してみないと分からない値ならどうでしょう。文字列 `"255"` を数に変えてから 1 を足します。

```rust title="src/main.rs"
fn main() {
    let x: u8 = "255".parse().expect("Not a number!");
    let y = x + 1;
    println!("255 + 1 = {y}");
}
```

debug ビルド（`cargo run`）と release ビルド（`cargo run --release`）で、結果が変わります。

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.00s
     Running `target\debug\data_types.exe`

thread 'main' (7680) panicked at src\main.rs:3:13:
attempt to add with overflow
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
error: process didn't exit successfully: `target\debug\data_types.exe` (exit code: 101)
❯ cargo run --release
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `release` profile [optimized] target(s) in 0.94s
     Running `target\release\data_types.exe`
255 + 1 = 0
```

debug では「足し算でオーバーフローした」で panic（プログラムがエラーで止まること）して、release では 0 に回り込みました。Book によると、release ではオーバーフローの検査を入れず、範囲を超えた値は一番小さい値に回り込みます。そのうえで、回り込みに頼るのは誤りだとしています。JavaScript なら、ふつうに 256 になるところです。

```console
❯ bun -e 'console.log(255 + 1)'
256
```

回り込んでほしいのか、エラーにしたいのかをはっきり書きたいときは、標準ライブラリのメソッドを使います。Book が紹介している 4 種類を、全部試してみます。

```rust title="src/main.rs"
fn main() {
    let x: u8 = "255".parse().expect("Not a number!");
    println!("wrapping_add: {}", x.wrapping_add(1));
    println!("checked_add: {:?}", x.checked_add(1));
    println!("saturating_add: {}", x.saturating_add(1));
    println!("overflowing_add: {:?}", x.overflowing_add(1));
}
```

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.23s
     Running `target\debug\data_types.exe`
wrapping_add: 0
checked_add: None
saturating_add: 255
overflowing_add: (0, true)
```

- `wrapping_add`：debug でも release でも回り込む
- `checked_add`：オーバーフローしたら `None`（値が無い）を返す
- `saturating_add`：一番大きい値（ここでは 255）で止まる
- `overflowing_add`：回り込んだ値と、オーバーフローしたかどうかを組で返す

`{:?}` は、`None` や組のような値を、デバッグ用の形で表示する書き方です。

### 割り算は切り捨て

整数どうしの割り算は、小数点以下を切り捨てます。

```rust title="src/main.rs"
fn main() {
    println!("5 / 2 = {}", 5 / 2);
    println!("-5 / 2 = {}", -5 / 2);
    println!("5 % 2 = {}", 5 % 2);
    println!("5.0 / 2.0 = {}", 5.0 / 2.0);
}
```

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.97s
     Running `target\debug\data_types.exe`
5 / 2 = 2
-5 / 2 = -2
5 % 2 = 1
5.0 / 2.0 = 2.5
```

`-5 / 2` が -3 ではなく -2 なので、0 に近いほうへの切り捨てです（Book にも「0 に向かって切り捨てる」とあります）。小数で割りたいなら `5.0 / 2.0` のように浮動小数点数（`f64`）どうしで割ります。JavaScript の割り算は切り捨てをしないので、Rust の動きに合わせるには `Math.trunc` が要ります。

```console
❯ bun -e 'console.log(5 / 2, -5 / 2, Math.trunc(-5 / 2))'
2.5 -2.5 -2
```

整数と小数を混ぜて割ることはできません。

```rust title="src/main.rs"
fn main() {
```

### char は 4 バイト

文字の型 `char` は、`'z'` のように一重引用符で書きます（文字列は二重引用符）。中身は Unicode のスカラー値 1 つなので、😻 のような絵文字も 1 つの `char` に入ります（肌の色付きや国旗のように、複数のスカラー値でできた絵文字は入りません）。

```rust title="src/main.rs"
fn main() {
    let c = 'z';
    let cat = '😻';
    println!("{c} {cat}");
    println!("char: {} bytes", size_of::<char>());
    println!("\"😻\" as a string: {} bytes, {} char", "😻".len(), "😻".chars().count());
}
```

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.05s
     Running `target\debug\data_types.exe`
z 😻
char: 4 bytes
"😻" as a string: 4 bytes, 1 char
```

`char` は 4 バイトです。文字列の `len()` は文字数ではなくバイト数を返すので、`"😻"` は 4 になりました。文字数を数えるなら `chars().count()` です。JavaScript の `length` は UTF-16 の単位で数えるので、同じ絵文字が 2 になります。

```console
❯ bun -e 'console.log("😻".length)'
2
```

### タプル

タプルは、型の違う値をまとめたものです。TypeScript のタプル型 `[number, number, number]` と似ていますが、Rust では値も `()` で書きます。

```rust title="src/main.rs"
fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
    let (x, y, z) = tup;
    println!("x = {x}, y = {y}, z = {z}");
    println!("tup.0 = {}", tup.0);
}
```

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 5.93s
     Running `target\debug\data_types.exe`
x = 500, y = 6.4, z = 1
tup.0 = 500
```

`let (x, y, z) = tup;` は分割代入で、JavaScript の `const [x, y, z] = tup` にあたります。要素は `tup.0` のように、`.` と番号で取り出します。無い番号の `tup.3` を足すと、コンパイルが通りません。

```rust title="src/main.rs"
fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
    let (x, y, z) = tup;
    println!("x = {x}, y = {y}, z = {z}");
    println!("tup.0 = {}", tup.0);
    println!("{}", tup.3);
}
```

```console
❯ cargo build

error[E0609]: no field `3` on type `(i32, f64, u8)`
 --> src\main.rs:6:24
  |
6 |     println!("{}", tup.3);

For more information about this error, try `rustc --explain E0609`.
error: could not compile `data_types` (bin "data_types") due to 1 previous error
```

何も無いタプル `()` は「ユニット」と呼ばれ、値が無いことを表します。このあと関数のところで、また出てきます。

### 配列は長さが決まっている

Rust の配列は、要素の型がすべて同じで、長さが決まっています。型は `[i32; 5]`（`i32` が 5 個）のように書きます。長さが違う配列を入れてみます。

```rust title="src/main.rs"
                break 'outer;
            }
            println!("i = {i}, j = {j}");
        }
    }
    println!("done");
}
```

## 章末の練習問題：フィボナッチ数

3 章の最後には、練習問題が 3 つあります。温度の変換、n 番目のフィボナッチ数、それに「クリスマスの 12 日」の歌詞の表示です。ここでは、オーバーフローの実例になるフィボナッチ数の問題を解いてみます。

```rust title="src/main.rs"

    let mut curr = 1;

        let next = prev + curr;
        prev = curr;
        curr = next;
```

```rust title="src/main.rs"
}

fn main() {
    for n in [48, 93, 94] {
        println!("fib({n}) = {}", fib(n));
    }
}
```

`u64` では 93 番目まで入って、94 番目で panic しました。`fib(48)` の正しい値は 4807526976 で、`u32` の release ビルドが出した 512559680 は、ここから 2 の 32 乗（4294967296）を引いた値です。回り込みが起きていたことが、数字でも確かめられます。

JavaScript の `number` は 2 の 53 乗を超えると、すべての整数を正確には表せなくなるので、`fib(93)` を正しく出すには `BigInt` が要ります。

`n` を付けない数は、末尾が `7000` に丸められてしまいました。Rust では、型を選ぶ時点で「どこまでの数を扱うか」を決めることになります。

## よく使うコマンド

| コマンド | 説明 |
| --- | --- |
| `cargo new <名前>` | 新しいプロジェクトを作る |
| `cargo run` | debug ビルドで実行する（オーバーフローを検査する） |
| `cargo run --release` | release ビルドで実行する（オーバーフローは回り込む） |
| `cargo build` | ビルドだけして、エラーを確かめる |

## まとめ

- `let` は変えられない、`let mut` は変えられる。同じ `let` でも、TypeScript とは「変えられる／変えられない」が逆
- `const` は型が必須で、コンパイルのときに決まる値しか入らない
- シャドーイングで、同じ名前の変数を作り直せる。`mut` と違って型も変えられる
- 整数の型は大きさと符号で分かれている。オーバーフローは debug では panic、release では回り込む。はっきりさせたいなら `checked_add` などを使う
- 整数の割り算は 0 に向かって切り捨て。整数と小数は混ぜられない
- `char` は 4 バイト。文字列の `len()` はバイト数
- 配列は長さまで型の一部。範囲の外を読むと panic する
- `let` は文で、ブロックや `if` は式。最後の `;` の無い式が値になる。`;` を付けると `()` になる
- `if` の条件は `bool` だけ。三項演算子のかわりに `if` を式として使う
- `loop` は `break` で値を返せる。ラベルで外側のループを指定できる。配列を回すなら `for`

次回は Book の 4 章、所有権です。Rust でいちばん特徴的なところで、TypeScript にはまったく無い考え方なので、エラーをたくさん見ることになりそうです。
