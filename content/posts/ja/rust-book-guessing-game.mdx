## このシリーズについて

[The Rust Programming Language](https://doc.rust-lang.org/book/)（通称「the Book」）は、Rust の公式の入門書です。Rust の公式サイトから無料で読めて、章ごとに実際にコードを書いて動かすように作られています。

このシリーズでは、Book を頭から順に、実際に手を動かして進めます。Book の文章やコードをそのまま写すのではなく、Book のとおりに動かした結果と、わざと書き換えて試した結果を載せます。Rust はコンパイラのエラーメッセージがとても丁寧なので、「こう書くとこう怒られる」を見るのが、いちばんの勉強になると思っています。Book のライセンスは MIT か Apache-2.0 の選択式です（[リポジトリの COPYRIGHT](https://github.com/rust-lang/book/blob/main/COPYRIGHT)）。

1 本目のこの記事は、Book の 1 章と 2 章です。

- 1 章：Rust を入れて、Hello, World! を動かす。Cargo を使う
- 2 章：数当てゲームを作る

公開中の Book は、[表紙](https://doc.rust-lang.org/book/title-page.html)で「Rust 1.97.0 以降、`edition = "2024"`」を前提にしています。この記事は Rust 1.99.1、mise 2026.10.11、Windows 11 の PowerShell で試しています。

## mise で Rust を入れる

Book は、Rust を [rustup](https://rustup.rs/) で入れるように案内しています。rustup は、Rust のコンパイラやツールを版ごとに入れて切り替える公式の道具です。このブログではツールを [mise](/ja/blog/getting-started-with-mise) でまとめて管理しているので、Rust も mise で入れます。

ただし、mise は Rust を自分で持つわけではありません。[mise の文書](https://mise.jdx.dev/lang/rust.html)によると、mise は裏で rustup を使って Rust を入れます。rustup が無ければ、まず rustup を入れます。Rust の本体は rustup の置き場所（既定では `~\.rustup` と `~\.cargo`）に入り、mise はそこへのリンクを持つだけです。

この記事の録画は、普段の環境を汚さないように、mise と rustup の置き場所を別のフォルダー（`C:\Users\Jam\rust-demo\home`）に向けて、まっさらな状態から撮りました。出力に出てくるパスは、普段なら `~\.cargo` などになります。

### mise use -g rust

`mise use -g rust` で、Rust をグローバルに入れます。`-g` は、どのフォルダーでも使える設定（グローバルの設定ファイル）に書くという意味です。版を書かないと、最新の安定版になります。

```console
❯ mise use -g rust
...
  rust@1.99.1  Downloading rustup-init  115.7s  12.7/12.7 MB · 111 kB/s
mise rust@1.99.1   1.99.1-x86_64-pc-windows-msvc installed - (timeout reading rustc version)
mise rust@1.99.1 info: default toolchain set to 1.99.1-x86_64-pc-windows-msvc
mise rust@1.99.1 info: checking for self-update (current version: 1.29.1)
mise rust@1.99.1 rustc 1.99.1 (58cf8f9c3 2026-10-13)
mise ✓ rust@1.99.1  136.0s
mise ████████████████ 1/1 · installed 1 tool in 136.0s
mise C:\Users\Jam\rust-demo\home\mise-config\config.toml tools: rust@1.99.1
```

途中で `rustup-init`（12.7 MB）をダウンロードして、Rust 1.99.1 を入れています。`rustup` の行が混ざっているのは、mise が rustup を呼んでいるからです。`installed` の行の `timeout reading rustc version` は、mise が、rustup が入れた直後の rustc の版を読みにいって時間切れになったという意味で、そのあとの行で版はちゃんと読めています。

設定ファイルには、`latest` と書かれました。録画では設定ファイルの場所も環境変数 `MISE_GLOBAL_CONFIG_FILE` で別にしています。普段なら `~\.config\mise\config.toml` です。

```console
❯ Get-Content $env:MISE_GLOBAL_CONFIG_FILE
[tools]
rust = "latest"
```

### 入ったものを確かめる

`rustc` がコンパイラ、`cargo` がビルドとパッケージ管理の道具、`rustup` が版の管理の道具です。

```console
❯ rustc --version

❯ cargo --version
cargo 1.99.1 (5f94df478 2026-08-27)
❯ rustup --version
rustup 1.29.1 (d95a37b6a 2026-08-13)
info: This is the version for the rustup toolchain manager, not the rustc compiler.
info: the currently active `rustc` version is `rustc 1.99.1 (58cf8f9c3 2026-10-13)`
❯ rustup toolchain list
1.99.1-x86_64-pc-windows-msvc (active, default)
```

`mise ls rust` を見ると、mise の側では「symlink」になっています。

```console
❯ mise ls rust
rust  1.99.1 (symlink)  C:\Users\Jam\rust-demo\home\mise-config\config.toml  latest
❯ Get-Item "$env:MISE_DATA_DIR\installs\rust\1.99.1" | Select-Object LinkType, Target | Format-List

LinkType : Junction
Target   : C:\Users\Jam\rust-demo\home\cargo\bin
```

mise のインストール先は、rustup が使う `cargo\bin` へのジャンクション（Windows のフォルダーのリンク）でした。mise は、どの版を使うかを `RUSTUP_TOOLCHAIN` という環境変数で rustup に伝えます。

```console
❯ mise env | Select-String RUSTUP_TOOLCHAIN

${Env:RUSTUP_TOOLCHAIN}='1.99.1'
```

つまり、mise で入れても、中で動いているのは rustup です。mise を使う利点は、ほかのツールと同じ設定ファイルで版を決められることです。

### Windows ではリンカーと Windows のライブラリが要る

`rustup toolchain list` に出ていた `x86_64-pc-windows-msvc` は、Rust の「ターゲット」の名前です。「64 ビットの Windows 向けに、Microsoft の MSVC の作法でビルドする」という意味で、Rust の側は `mise use -g rust` でもう揃っています。

足りなくなるのは、Rust の外にあるものです。MSVC のターゲットは、コンパイルした部品をつなぎ合わせて `.exe` にする「リンカー」と、Windows の標準のライブラリ（C のランタイムと Windows SDK）を、Visual Studio のものから借ります。Book の[インストールの節](https://doc.rust-lang.org/book/ch01-01-installation.html)にも、Windows では Visual Studio を入れるように書かれています。

この記事を試したマシンには、Visual Studio の C++ ビルドツールがすでに入っていました。Visual Studio のインストーラーに付いてくる `vswhere` で確かめられます。

```console
❯ & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -products * -property displayName
Visual Studio Build Tools 2026
❯ & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools
```

2 つ目のコマンドは、C++ のツール（`VC.Tools.x86.x64`）を含む Visual Studio を探しています。何も出なければ、入っていません。

#### 基本の入れ方：winget

mise の登録ツールには、Visual Studio のビルドツールはありません。基本は、rustup の[文書](https://rust-lang.github.io/rustup/installation/windows-msvc.html)にある winget の 1 行で入れます。

```powershell
winget install --id Microsoft.VisualStudio.Community --source winget --force --override "--add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 --add Microsoft.VisualStudio.Component.VC.Tools.ARM64 --add Microsoft.VisualStudio.Component.Windows11SDK.22621 --addProductLang En-us"
```

C++ のツール（x64 と ARM64）と Windows 11 SDK、英語の言語パックを、Visual Studio Community と一緒に入れるコマンドです。Community は個人なら無料で使えます。rustup の文書によると、すでに Visual Studio のライセンスを持っているなら、`Community` を `BuildTools` に置き換えてもかまいません。このマシンにはすでに入っていたので、このコマンドは実行していません。

#### mise で揃えるなら：xwin と rust-lld

Visual Studio を入れずに、mise だけで揃える方法もあります。[xwin](https://github.com/Jake-Shadle/xwin) は、MSVC の C のランタイムと Windows SDK のライブラリとヘッダーだけを Microsoft から取ってきて、フォルダーに展開する道具です。リンカーには、Rust に同梱されている `rust-lld` を使います。公式の手順ではありませんが、録画用の環境で試したところ、数当てゲームをビルドして動かせました。

xwin は mise の登録ツールにはありませんが、GitHub のリリースから入れる `github:` の書き方で入ります。

```console
❯ mise use -g github:Jake-Shadle/xwin
...
mise ✓ github:Jake-Shadle/xwin@0.10.0  19.7s  xwin-0.10.0-x86_64-pc-windows-msvc.tar.gz
mise ████████████████ 1/1 · installed 1 tool in 19.7s
mise C:\Users\Jam\rust-demo\home\mise-config\config.toml tools: github:Jake-Shadle/xwin@0.10.0
❯ xwin --version
xwin 0.10.0
```

`xwin splat` で、ライブラリをダウンロードして展開します。`--accept-license` は Microsoft のライセンスに同意するという意味なので、内容を確かめてから付けてください。`--disable-symlinks` は、大文字と小文字の違いを吸収するためのシンボリックリンクを作らない指定です。Windows のファイルシステムは大文字と小文字を区別しないので要りませんし、Windows でシンボリックリンクを作るには、権限が要ることがあります。

```console
❯ xwin --accept-license --cache-dir C:\Users\Jam\rust-demo\home\xwin-cache splat --disable-symlinks --output C:\Users\Jam\rust-demo\home\xwin
❯ Get-ChildItem -Name xwin, xwin\crt\lib, xwin\sdk\lib
crt
sdk
x86_64
10.0.26100
ucrt
um
```

この回線では、終わるまでに 666 秒かかりました。展開したライブラリは 618 MB で、ダウンロードのキャッシュ（`--cache-dir` の場所）がほかに 1.1 GB あります。キャッシュは、終わったら消してかまいません。

あとは、Cargo にリンカーとライブラリの場所を教えます。プロジェクトの `.cargo\config.toml` に書きます。

```toml title=".cargo/config.toml"
[target.x86_64-pc-windows-msvc]
linker = "rust-lld"
rustflags = [
  "-Lnative=C:/Users/Jam/rust-demo/home/xwin/crt/lib/x86_64",
  "-Lnative=C:/Users/Jam/rust-demo/home/xwin/sdk/lib/um/x86_64",
  "-Lnative=C:/Users/Jam/rust-demo/home/xwin/sdk/lib/ucrt/x86_64",
]
```

#### C のコードを含むクレート

数当てゲームが使うクレートは、すべて Rust だけで書かれています。ところが、世の中のクレートには、中に C のコードを含んでいて、ビルドのときに C のコンパイラを呼ぶものがあります。xwin が用意するのはライブラリとヘッダーだけで、C のコンパイラは入っていません。

確かめるために、C の関数を 1 つ呼ぶだけの小さなクレート `cdemo` を作りました。`build.rs` は、ビルドの前に Cargo が実行するスクリプトです。ここでは [cc](https://crates.io/crates/cc) クレートを使って、`greet.c` をコンパイルしています。

```c title="src/greet.c"
#include <string.h>

int c_len(const char *text) {
    return (int)strlen(text);
}
```

```rust title="build.rs"
fn main() {
    cc::Build::new().file("src/greet.c").compile("greet");
}
```

```rust title="src/main.rs"
use std::ffi::{c_char, c_int};

unsafe extern "C" {
    fn c_len(text: *const c_char) -> c_int;
}

fn main() {
    let len = unsafe { c_len(c"Hello from C".as_ptr()) };
    println!("C says the text is {len} bytes long");
}
```

`unsafe` や `extern "C"` は、Book の 20 章で出てくる、C の関数を呼ぶための書き方です。ここでは中身は気にしなくてかまいません。

同じランナーで、xwin の設定だけでこのクレートをビルドすると、C のコンパイラが見つからずに失敗しました。

```text
  error occurred in cc-rs: failed to find tool "cl.exe": program not found
```

C のコンパイラも mise で入れます。mise の登録ツールにある `clang`（[conda-forge](https://conda-forge.org/) のパッケージを入れる `conda:clang`）に、MSVC と同じ作法でコンパイルする `clang-cl` が入っています。静的ライブラリを作る道具は、Rust の `llvm-tools` コンポーネントの `llvm-ar` を使います。

```powershell
mise use -g conda:clang
rustup component add llvm-tools
```

cc クレートには、どのコンパイラと、静的ライブラリにまとめる道具を使い、どこのヘッダーを読むかを環境変数で教えます。`/imsvc` は、xwin が展開したヘッダーのフォルダーを、システムのヘッダーとして読ませる clang-cl のオプションです。

```powershell
$x = "C:/Users/Jam/rust-demo/home/xwin"
$env:CC_x86_64_pc_windows_msvc = Join-Path (mise where conda:clang) "Library\bin\clang-cl.exe"
$env:AR_x86_64_pc_windows_msvc = (Get-ChildItem -Recurse -Filter llvm-ar.exe (rustc --print sysroot)).FullName | Select-Object -First 1
$env:CFLAGS_x86_64_pc_windows_msvc = "/imsvc $x/crt/include /imsvc $x/sdk/include/ucrt /imsvc $x/sdk/include/um /imsvc $x/sdk/include/shared"
```

ランナーでは、これで C の関数を呼ぶクレートもビルドして動かせました（ランナーでの xwin の場所は `D:/a/_temp/xwin` です）。

```text
CC = C:\Users\runneradmin\AppData\Local\mise\installs\conda-clang\23.1.3\Library\bin\clang-cl.exe
AR = C:\Users\runneradmin\.rustup\toolchains\1.99.1-x86_64-pc-windows-msvc\lib\rustlib\x86_64-pc-windows-msvc\bin\llvm-ar.exe
   Compiling cdemo v0.1.0 (D:\a\_temp\work\cdemo)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.45s
C says the text is 12 bytes long
```

#### どちらを選ぶか

xwin の README には、Windows 以外の環境から Windows 向けにコンパイルしてリンクするための道具だと書かれています。Windows の上で使うのは、本来の用途ではありません。ここで試した範囲では動きましたが、もっと大きなクレートや、C++ を含むクレートまでは試していません。迷ったら、winget で Visual Studio を入れるのが確実です。mise だけで揃えたい、Visual Studio を入れたくない、という場合に xwin を試してみてください。

## Hello, World!（1.2 節）

まずは Cargo を使わずに、コンパイラの `rustc` を直接使います。`hello_world` というフォルダーを作って、`main.rs` を書きます。

```rust title="main.rs"
fn main() {
    println!("Hello, world!");
}
```

`fn main()` が、プログラムが始まる関数です。`rustc main.rs` でコンパイルします。

```console
❯ rustc main.rs
❯ Get-ChildItem -Name
main.exe
```

### 関数とマクロの違い

`println!` の最後の `!` は、これが関数ではなく**マクロ**だという印です。JavaScript や Python にはマクロが無いので、少し説明します。

**関数**は、決まった数と型の引数を受け取って、プログラムが動いているときに呼ばれるものです。`fn main()` も関数です。

**マクロ**は、コンパイルの前に、書いたコードを別のコードに書き換える仕組みです。Book の[マクロの節](https://doc.rust-lang.org/book/ch20-05-macros.html)は「コードを書くコード」と説明しています。`println!("Hello, world!")` は、コンパイルのときに、文字列を組み立てて画面に出すための、もっと長いコードに展開されます。展開はコンパイラが勝手にやるので、ふだん展開されたコードを見ることはありません。

違いが分かりやすいのは、引数の数です。Rust の関数は、引数の数が決まっています。引数を 1 つ受け取る関数 `greet` に、2 つ渡してみます。

```rust title="fn_args.rs"
fn greet(name: &str) {
    println!("Hello, {name}!");
}

fn main() {
    greet("Rust");
    greet("Rust", 11);
}
```

```console
❯ rustc fn_args.rs
error[E0061]: this function takes 1 argument but 2 arguments were supplied
 --> fn_args.rs:7:5
  |
7 |     greet("Rust", 11);
  |     ^^^^^         -- unexpected argument #2 of type `{integer}`
  |
note: function defined here
 --> fn_args.rs:1:4
  |
1 | fn greet(name: &str) {
  |    ^^^^^
help: remove the extra argument
  |
7 -     greet("Rust", 11);
7 +     greet("Rust");
  |

error: aborting due to 1 previous error

For more information about this error, try `rustc --explain E0061`.
```

「1 つしか受け取らない関数に 2 つ渡している」と怒られました。Rust には、TypeScript の省略できる引数（`name?: string`）や、JavaScript の `...args` のような、数が変わる引数の関数はありません。

ところが、`println!` は引数がいくつでも書けます。

```rust title="varargs.rs"
fn main() {
    let name = "Rust";
    let age = 11;
    println!("Hello!");
    println!("Hello, {name}!");
    println!("Hello, {}! You are {} years old.", name, age);
}
```

```console
❯ rustc varargs.rs
❯ .\varargs.exe
Hello!
Hello, Rust!
Hello, Rust! You are 11 years old.
```

引数が 1 つでも 3 つでも動きました。2 つ目の `println!` のように、文字列の中に `{name}` と変数の名前を直接書くこともできます。マクロはコンパイルの前に書いたコードそのものを読むので、こういうことができます。

もう 1 つの利点は、間違いがコンパイルのときに見つかることです。`{}` が 2 つあるのに、引数を 1 つしか渡さないとどうなるでしょうか。

```console
❯ Get-Content too_few.rs
fn main() {
    let name = "Rust";
    println!("Hello, {}! You are {} years old.", name);
}
❯ rustc too_few.rs
error: 2 positional arguments in format string, but there is 1 argument
 --> too_few.rs:3:22
  |
3 |     println!("Hello, {}! You are {} years old.", name);
  |                      ^^          ^^              ----

error: aborting due to 1 previous error
```

実行する前に、コンパイルの段階で「`{}` は 2 つなのに、引数は 1 つ」と止められました。`println!` は、展開するときに書式の文字列を読んで、`{}` と引数の数を突き合わせているのです。ふつうの関数では、文字列の中身まではコンパイラに見えないので、こうはいきません。

マクロはこのシリーズで何度も出てきます。自分でマクロを書く方法は、Book の 20 章で扱います。ここでは「名前の最後に `!` があればマクロで、コンパイルの前にコードに展開される」とだけ覚えておけば十分です。

### ! を消してみる

`!` を消すとどうなるか、`println(` に書き換えた `no_bang.rs` で試します。

```console
❯ Get-Content no_bang.rs
fn main() {
    println("Hello, world!");
}
❯ rustc no_bang.rs
error[E0423]: cannot find function `println` in this scope
 --> no_bang.rs:2:5
  |
2 |     println("Hello, world!");
  |     ^^^^^^^ not found in this scope
  |
  = note: a macro named `println` exists in another namespace
help: use `!` to invoke the macro
  |
2 |     println!("Hello, world!");
  |            +

error: aborting due to 1 previous error

For more information about this error, try `rustc --explain E0423`.
```

「`println` という関数は無い。`println` という名前のマクロならある。`!` を付けて呼べ」と、直し方まで教えてくれます。`+` の行が、足すべき文字の位置です。エラーには `E0423` のような番号が付いていて、`rustc --explain E0423` で詳しい説明を読めます。

### ; を消してみる

今度は、行の最後の `;` を消した `no_semi.rs` です。

```console

❯ .\no_semi.exe
```

これはエラーになりませんでした。Rust では、ブロックの最後の式は `;` が無くてもよく、その値がブロックの値になります。`println!` が返すのは「何もない」という値（`()`）で、`main` が返すのもそれなので、問題になりません。この話は 3 章でちゃんと出てくるので、そこでまた試します。

## Hello, Cargo!（1.3 節）

実際の Rust のプロジェクトでは、`rustc` を直接呼ぶことはほとんどなく、**Cargo** を使います。Cargo は、ビルド、実行、テスト、依存するパッケージ（Rust では「クレート」と呼びます）の管理までを 1 つでこなす道具です。JavaScript で言えば、npm とビルドの道具を合わせたようなものです。

`rustc` は Rust のコンパイラそのもので、`.rs` のファイルを受け取って実行ファイルやライブラリを作ります。Cargo はコンパイラではありません。どのファイルを、どの順で、どんな設定でコンパイルするかを決めて、`rustc` を呼ぶ役です。TypeScript で言えば、`rustc` が `tsc`、Cargo が npm と `tsc` を呼ぶスクリプトをまとめたもの、という関係です。

## 数当てゲームを作る（2 章）

2 章では、1 から 100 までの秘密の数を当てるゲームを作ります。Book は、少しずつコードを足しながら、Rust の基本をひととおり見せてくれます。ここでも同じ順に進めます。

```console

```

ゲームは標準入力から数を読むので、この記事では PowerShell で入力をパイプで流して動かしています。そのため、入力した値そのものは画面に出ません。

### 入力を読む

最初は、入力を 1 行読んで、そのまま表示するだけです。

```rust title="src/main.rs"
use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}
```

```console
❯ "42" | cargo run
   Compiling guessing_game v0.1.0 (C:\Users\Jam\rust-demo\work\guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 4.00s
     Running `target\debug\guessing_game.exe`
Guess the number!
Please input your guess.
You guessed: 42

```

最後に空の行が出ているのは、`read_line` が読んだ行の最後の改行まで `guess` に入れているからです。これはあとで効いてきます。

ここには、Rust らしいところが 3 つ詰まっています。

- `let mut guess`：Rust の変数は、既定では**変更できません**。`mut` を付けたときだけ変更できます
- `&mut guess`：`read_line` に、`guess` を「書き換えてよい参照」として渡しています。`&` が参照で、4 章の所有権の話につながります
- `.expect(...)`：`read_line` は、成功か失敗かを表す `Result` を返します。`expect` は、失敗だったらそのメッセージでプログラムを止めます

### mut を消してみる

`let mut guess` を `let guess` にすると、どうなるでしょうか。


「変更できると宣言していないので、変更できる形では借りられない」というエラーです。TypeScript の `const` は「変数に別の値を入れ直せない」だけで、中身のオブジェクトは書き換えられます。Rust の `mut` が無い変数は、中身も書き換えられません（`Cell` のように、わざと中身の書き換えを許す型は別で、Book の 15 章で出てきます）。

```rust title="src/main.rs"
    // --snip--
}
```

### 比べる：型が違うと比べられない

入力した数と秘密の数を比べます。`std::cmp::Ordering` を使い、`match` で「小さい」「大きい」「同じ」に分けます。

```rust title="src/main.rs"
use std::cmp::Ordering;

// ...

    println!("You guessed: {guess}");

    match guess.cmp(&secret_number) {
        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),
        Ordering::Equal => println!("You win!"),
    }
```

### 文字列を数に変える

入力を数に変えてから比べます。Book は、`guess` という同じ名前で新しい変数を作り直します。

```rust title="src/main.rs"
    let guess: u32 = guess.trim().parse().expect("Please type a number!");
```

同じ名前の変数を `let` でもう一度作ると、前の変数は隠れます。これを**シャドーイング**と呼びます。`guess_str` と `guess_num` のように名前を分けなくて済みます。`trim()` で前後の空白と改行を取り、`parse()` で数に変えます。`u32` は 32 ビットの符号なし整数です。


今度は比べられました。`You guessed: 50` のあとの空行も消えています。`trim()` で改行を取ったからです。

ここで面白いのは、`secret_number` の型をどこにも書いていないことです。`guess` を `u32` にして `guess.cmp(&secret_number)` で比べたので、Rust は「`secret_number` も `u32` のはずだ」と推論しています。

`-q` は、Cargo 自身の `Compiling` などの表示を消すオプションです。Rust では、このようにプログラムが止まることを **panic** と呼びます。

### 繰り返して、数字以外は受け流す

![入力文字列の空白と改行を trim で除き、parse で u32 に変換する。成功した数値は比較し、変換に失敗した入力は continue で受け流す](/rust/guess-input.avif)

最後に、当たるまで何度でも入力できるようにします。Book の完成形は、全体を `loop` で囲み、当たったら `break` で抜けます。数でないものを入れても止まらないように、`expect` の代わりに `match` で `parse()` の結果を分けます。秘密の数の表示も消します。Book のリスト 2-6 と同じコードです。

```rust title="src/main.rs"
use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    loop {
        println!("Please input your guess.");

        let mut guess = String::new();

        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let guess: u32 = match guess.trim().parse() {
            Ok(num) => num,
            Err(_) => continue,
        };

        println!("You guessed: {guess}");

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Too small!"),
            Ordering::Greater => println!("Too big!"),
            Ordering::Equal => {
                println!("You win!");
                break;
            }
        }
    }
}
```

`parse()` は `Result` を返し、成功なら `Ok(数)`、失敗なら `Err(エラー)` です。`Ok(num) => num` で数を取り出し、`Err(_) => continue` で、失敗したらループの最初に戻ります。`_` は「中身は使わない」という意味です。

秘密の数が見えなくなったので、`abc` のあとに 1 から 100 までを順に流して、当たるまで動かします。

```console
❯ $out = @("abc") + (1..100) | cargo run -q
❯ $out | Select-Object -First 9
Guess the number!
Please input your guess.
Please input your guess.
You guessed: 1
Too small!
Please input your guess.
You guessed: 2
Too small!
Please input your guess.
❯ $out | Select-Object -Last 6
Please input your guess.
You guessed: 91
Too small!
Please input your guess.
You guessed: 92
You win!
```

`Please input your guess.` が 2 回続いているところが、`abc` を受け流した跡です。92 で当たって、`You win!` のあとはループを抜けて終わりました。残りの 93 から 100 は、読まれずに捨てられています。

## 実際に踏んだ罠：入力が尽きると止まらない

入力をパイプで流していて、困ったことが 1 つありました。当たる前に入力が尽きると、プログラムが止まらなくなります。`50` だけを流して、最初の 8 行だけを見ます。

```console
❯ "50" | cargo run -q | Select-Object -First 8
Guess the number!
Please input your guess.
You guessed: 50
Too small!
Please input your guess.
Please input your guess.
Please input your guess.
Please input your guess.
```

`Select-Object -First 8` で切らなければ、`Please input your guess.` が延々と出続けます。入力が尽きると、`read_line` は失敗ではなく「0 バイト読んだ」という成功を返します。`guess` は空のままなので、`parse()` が失敗して `continue` し、また `read_line` が 0 バイトを返す、を繰り返すのです。キーボードから遊ぶぶんには、ふつうは起きません。ただ、テストで入力を流すときは同じことが起きますし、Windows で `Ctrl+Z` と Enter で入力を終わらせたときも、同じ理屈で起きるはずです（こちらは試していません）。

`read_line` が返す読んだバイト数を見て、0 なら抜ける、と書けば直ります。ただ、Book の流れを崩さないように、この記事では直さずにおきます。

## まとめ

- mise で Rust を入れても、中で動いているのは rustup。mise は `RUSTUP_TOOLCHAIN` で版を伝える
- Windows では、リンカーと Windows のライブラリのために Visual Studio の C++ ビルドツールが要る。基本は winget で入れる。mise だけで揃えるなら、xwin と `rust-lld` で、Visual Studio を消した Windows のランナーでもビルドして動かせた。C のコードを含むクレートは、`conda:clang` の clang-cl と `llvm-tools` の llvm-ar を足し、環境変数で教えればビルドできた
- `rustc` で直接コンパイルすると、実行ファイル（`.exe`）ができる。ふだんは Cargo の `build` / `run` / `check` を使う
- `Cargo.toml` は `package.json`、`Cargo.lock` は `package-lock.json`。`"0.10.1"` は「0.10.1 以上、0.11.0 未満」
- 変数は既定で変更できない。`Result` を無視すると警告、トレイトは `use` しないとメソッドが使えない、型が違うものは比べられない
- コンパイラのエラーは、何が悪いかだけでなく、直し方まで教えてくれる。壊して読むのがいちばんの勉強になる
