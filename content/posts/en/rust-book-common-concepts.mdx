## Variables and mutability (section 3.1)

### No second assignment

[Section 3.1](https://doc.rust-lang.org/book/ch03-01-variables-and-mutability.html) starts where the last post left
off: variables cannot be changed by default. Assign to a `let` variable a second time:

```rust title="src/main.rs"
fn main() {
    let x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}
```

```console
❯ cargo run
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
error[E0384]: cannot assign twice to immutable variable `x`
 --> src\main.rs:4:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     println!("The value of x is: {x}");
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++

For more information about this error, try `rustc --explain E0384`.
error: could not compile `variables` (bin "variables") due to 1 previous error
```

Last time it was `E0596`, "cannot borrow as mutable"; this time it is `E0384`, "cannot assign twice to immutable
variable". The fix is `mut` in both cases, and the `+++` marks exactly where it goes.

Side by side with TypeScript:

| What you want | TypeScript | Rust |
| --- | --- | --- |
| A variable that never changes | `const x = 5` | `let x = 5` |
| A variable that changes later | `let x = 5` | `let mut x = 5` |
| A constant fixed at compile time | (no dedicated mechanism) | `const X: i32 = 5;` |

The same word `let` means "can change" in TypeScript and "cannot change" in Rust, which is confusing at first.

### Constants need a type

Rust's `const` is a different thing from TypeScript's. Unlike `let`, it always takes a type. Leave it out:

```rust title="src/main.rs"
const MAX_POINTS = 100_000;

fn main() {
    println!("{MAX_POINTS}");
}
```

```console
❯ cargo build
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
error: missing type for `const` item
 --> src\main.rs:1:17
  |
1 | const MAX_POINTS = 100_000;
  |                 ^ help: provide a type for the constant: `: i32`

error: could not compile `variables` (bin "variables") due to 1 previous error
```

"Provide a type, for example `: i32`." The `_` in `100_000` is only a digit separator for readability; the value is
100000.

The other difference is that a constant's value has to be known at compile time. Try a value that is only known by
running the program:

```rust title="src/main.rs"
fn main() {
    let input = String::from("42");
    const LIMIT: usize = input.len();
    println!("{LIMIT}");
}
```

```console

error[E0435]: attempt to use a non-constant value in a constant
 --> src\main.rs:3:26
  |
```

"Attempt to use a non-constant value in a constant; how about `let`?" TypeScript's `const` takes any value,
runtime ones included, so this is a big difference. It helps to think of a Rust `const` as a named value baked
into the program.

### Shadowing

Rust lets you create a variable with the same name again and again with `let`. This is called shadowing.

```rust title="src/main.rs"
fn main() {
    let x = 5;
    let x = x + 1;
    {
        let x = x * 2;
        println!("inner x: {x}");
    }
    println!("outer x: {x}");
}
```

```console
❯ cargo run
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.72s
     Running `target\debug\variables.exe`
inner x: 12
outer x: 6
```

`x` is created as 5, recreated as 6, and inside the `{}` it becomes 12. Leaving the `{}` drops the inner `x`, and the
outer 6 is back. Nothing was overwritten with `mut`; a new variable was created under the same name.

Two `let`s for the same name in one scope do not even run in JavaScript:

```console
❯ bun -e 'let x = 5; let x = 6;'
1 | let x = 5; let x = 6;
                   ^
error: "x" has already been declared
    at C:\Users\Jam\rust-demo\work\[eval]:1:16

1 | let x = 5; let x = 6;
        ^
note: "x" was originally declared here
   at C:\Users\Jam\rust-demo\work\[eval]:1:5

Bun v1.4.2 (Windows x64)
```

Where shadowing shines is changing the type. Replace a string of spaces with how many there are:

```rust title="src/main.rs"
fn main() {
    let spaces = "   ";
    let spaces = spaces.len();
    println!("{spaces}");
}
```

```console
❯ cargo run
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.54s
     Running `target\debug\variables.exe`
3
```

Doing the same with `let mut` and an assignment is an error:

```rust title="src/main.rs"
fn main() {
    let mut spaces = "   ";
    spaces = spaces.len();
    println!("{spaces}");
}
```

```console
❯ cargo build
   Compiling variables v0.1.0 (C:\Users\Jam\rust-demo\work\variables)
error[E0308]: mismatched types
 --> src\main.rs:3:14
  |
2 |     let mut spaces = "   ";
  |                      ----- expected due to this value
3 |     spaces = spaces.len();
  |              ^^^^^^^^^^^^ expected `&str`, found `usize`

For more information about this error, try `rustc --explain E0308`.
error: could not compile `variables` (bin "variables") due to 1 previous error
```

`mut` means "the value can change", not "the type can change". `spaces` got its type, a string (`&str`), from its first
value, so a number (`usize`) cannot go in. Last time's guessing game recreated `guess` with
`let guess: u32 = guess.trim().parse()...`; that was shadowing too, and it spares you names like `guess_str` and
`guess_num`.

## Data types (section 3.2)

[Section 3.2](https://doc.rust-lang.org/book/ch03-02-data-types.html) is about types. Rust is statically typed:
every variable's type has to be known at compile time. Most of the time it is inferred, but when it cannot be, the
compiler asks for one. `parse()`, seen last time, is the example:

```rust title="src/main.rs"
fn main() {
    let guess = "42".parse().expect("Not a number!");
    println!("{guess}");
}
```

```console

   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
error[E0284]: type annotations needed
 --> src\main.rs:2:9
  |
2 |     let guess = "42".parse().expect("Not a number!");

  |

  = note: the type must also implement `FromStr`
note: required by a bound in `core::str::<impl str>::parse`
 --> /rustc/58cf8f9c35b355199727627d07ae34a4e2846d67/library\core\src\str\mod.rs:2782:4
```

It cannot tell what type `"42"` should become, so it asks for a type on `guess`. The error code differs from last

### Integer types

JavaScript basically has a single kind of number, `number`. Rust has many integer types, split by size and sign.

| Size | Signed | Unsigned |
| --- | --- | --- |
| 8 bits | `i8` | `u8` |
| 16 bits | `i16` | `u16` |
| 32 bits | `i32` | `u32` |
| 64 bits | `i64` | `u64` |
| 128 bits | `i128` | `u128` |
| Machine-dependent | `isize` | `usize` |

`i` is signed (negatives allowed) and `u` is unsigned (zero and up). An integer written without a type is an
`i32`. `usize` is the type for array indices and lengths; it is what `spaces.len()` returned above.

### Integer overflow

![With default build settings, runtime u8 overflow panics in debug and wraps to zero in release. Overflow known at compile time is an error](/rust/integer-overflow.avif)

Each type has a fixed range, so the natural question is what happens beyond it. A `u8` holds 0 to 255. First, the
straightforward `255 + 1`:

```rust title="src/main.rs"
fn main() {
    let x: u8 = 255 + 1;
    println!("{x}");
}
```

```console
❯ cargo build
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
error: this arithmetic operation will overflow
 --> src\main.rs:2:17
  |
2 |     let x: u8 = 255 + 1;
  |                 ^^^^^^^ attempt to compute `u8::MAX + 1_u8`, which would overflow
  |
  = note: `#[deny(arithmetic_overflow)]` on by default

error: could not compile `data_types` (bin "data_types") due to 1 previous error
```

The value is known at compile time, so the compiler catches it. What about a value only known at run time? Parse
the string `"255"` into a number, then add 1:

```rust title="src/main.rs"
fn main() {
    let x: u8 = "255".parse().expect("Not a number!");
    let y = x + 1;
    println!("255 + 1 = {y}");
}
```

Debug builds (`cargo run`) and release builds (`cargo run --release`) give different results.

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.00s
     Running `target\debug\data_types.exe`

thread 'main' (7680) panicked at src\main.rs:3:13:
attempt to add with overflow
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
error: process didn't exit successfully: `target\debug\data_types.exe` (exit code: 101)
❯ cargo run --release
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `release` profile [optimized] target(s) in 0.94s
     Running `target\release\data_types.exe`
255 + 1 = 0
```

The debug build panics (stops with an error) with "attempt to add with overflow"; the release build wraps to 0.
According to the Book, release builds leave out the overflow checks and wrap values past the maximum around to the
minimum, and relying on that wrapping is considered an error. In JavaScript it is simply 256:

```console
❯ bun -e 'console.log(255 + 1)'
256
```

To say explicitly whether you want wrapping or an error, the standard library has methods for it. Here are all four
families the Book lists:

```rust title="src/main.rs"
fn main() {
    let x: u8 = "255".parse().expect("Not a number!");
    println!("wrapping_add: {}", x.wrapping_add(1));
    println!("checked_add: {:?}", x.checked_add(1));
    println!("saturating_add: {}", x.saturating_add(1));
    println!("overflowing_add: {:?}", x.overflowing_add(1));
}
```

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.23s
     Running `target\debug\data_types.exe`
wrapping_add: 0
checked_add: None
saturating_add: 255
overflowing_add: (0, true)
```

- `wrapping_add`: wraps in debug and release alike
- `checked_add`: returns `None` (no value) on overflow
- `saturating_add`: stops at the maximum (255 here)
- `overflowing_add`: returns the wrapped value paired with whether it overflowed

`{:?}` prints values such as `None` or a pair in their debug form.

### Division truncates

Dividing two integers drops the fractional part.

```rust title="src/main.rs"
fn main() {
    println!("5 / 2 = {}", 5 / 2);
    println!("-5 / 2 = {}", -5 / 2);
    println!("5 % 2 = {}", 5 % 2);
    println!("5.0 / 2.0 = {}", 5.0 / 2.0);
}
```

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.97s
     Running `target\debug\data_types.exe`
5 / 2 = 2
-5 / 2 = -2
5 % 2 = 1
5.0 / 2.0 = 2.5
```

`-5 / 2` is -2, not -3, so it truncates toward zero (the Book says the same). To divide with decimals, divide two
floating-point numbers (`f64`) such as `5.0 / 2.0`. In JavaScript division never truncates, so matching
Rust takes `Math.trunc`:

```console
❯ bun -e 'console.log(5 / 2, -5 / 2, Math.trunc(-5 / 2))'
2.5 -2.5 -2
```

Integers and floats cannot be mixed in a division:

```rust title="src/main.rs"
fn main() {
    let half = 5 / 2.0;
    println!("{half}");
}
```

read it as "`/` is defined separately for each pair of types".

### char is 4 bytes

The character type `char` is written in single quotes, like `'z'` (strings take double quotes). It holds one
Unicode scalar value, so an emoji such as 😻 fits in a single `char` (emoji built from several scalar values,
such as flags or skin tones, do not).

```rust title="src/main.rs"
fn main() {
    let c = 'z';
    let cat = '😻';
    println!("{c} {cat}");
    println!("char: {} bytes", size_of::<char>());
    println!("\"😻\" as a string: {} bytes, {} char", "😻".len(), "😻".chars().count());
}
```

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.05s
     Running `target\debug\data_types.exe`
z 😻
char: 4 bytes
"😻" as a string: 4 bytes, 1 char
```

A `char` is 4 bytes. A string's `len()` counts bytes, not characters, so `"😻"` is 4; `chars().count()` counts
characters. JavaScript's `length` counts UTF-16 units, so the same emoji is 2:

```console
❯ bun -e 'console.log("😻".length)'
2
```

### Tuples

A tuple groups values of different types. It resembles TypeScript's tuple types such as `[number, number, number]`,
but in Rust both the type and the value are written with `()`.

```rust title="src/main.rs"
fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
    let (x, y, z) = tup;
    println!("x = {x}, y = {y}, z = {z}");
    println!("tup.0 = {}", tup.0);
}
```

```console
❯ cargo run
   Compiling data_types v0.1.0 (C:\Users\Jam\rust-demo\work\data_types)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 5.93s
     Running `target\debug\data_types.exe`
x = 500, y = 6.4, z = 1
tup.0 = 500
```

`let (x, y, z) = tup;` is destructuring, the counterpart of JavaScript's `const [x, y, z] = tup`. Elements are read
with a `.` and their position, as in `tup.0`. Adding a `tup.3` that does not exist stops the build:

```rust title="src/main.rs"
fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
    let (x, y, z) = tup;
    println!("x = {x}, y = {y}, z = {z}");
    println!("tup.0 = {}", tup.0);
    println!("{}", tup.3);
}
```

### Arrays have a fixed length

A Rust array holds elements of one type and has a fixed length. Its type is written like `[i32; 5]` (five
`i32`s). Assign an array of a different length:

```rust title="src/main.rs"
fn main() {
    let a: [i32; 5] = [1, 2, 3];
    println!("{a:?}");
}
```

```console

  |            |
```

## Functions (section 3.3)

### Parameters need types

[Section 3.3](https://doc.rust-lang.org/book/ch03-03-how-functions-work.html) covers functions. They are defined
with `fn`, and Rust's convention is `snake_case` names (lowercase with `_`). Parameters always take a type. Leave it
out:

```rust title="src/main.rs"
fn main() {
    print_twice(5);
}

fn print_twice(x) {
    println!("{x} {x}");
}
```

It is treated as a syntax error, not a missing annotation. In TypeScript an untyped parameter becomes `any` and
passes (unless `noImplicitAny` is on), but Rust does not infer the types of function parameters: a function's
outward shape is always written out. Calling `print_twice` even though it is defined after `main` works, as with
JavaScript function declarations.

### Statements and expressions

A key to reading Rust is the difference between **statements** and **expressions**.

- Statement: does something and returns no value. `let y = 6;` is a statement
- Expression: evaluates to a value. `5 + 6`, a function call and a `{}` block are all expressions

`let` is a statement, so it has no value. Write it the way JavaScript's `x = y = 6` would work:

```rust title="src/main.rs"
fn main() {
    let x = (let y = 6);
}
```

```console
 --> src\main.rs:2:14
```

A `{}` block, on the other hand, is an expression and has a value:

The point is that the last line, `x + 1`, has no `;`. An expression without a `;` at the end of a block becomes the
value of the whole block.

### Return values and the trailing semicolon

## Control flow (section 3.5)

### if conditions must be bool

[Section 3.5](https://doc.rust-lang.org/book/ch03-05-control-flow.html) covers `if` and loops. `if` looks almost
like JavaScript's, except that the condition needs no `()`. The real difference is that the condition must be a
`bool`.

```rust title="src/main.rs"
fn main() {
    let number = 3;

    if number {
        println!("number was three");
    }
}
```

```console
❯ cargo build
   Compiling branches v0.1.0 (C:\Users\Jam\rust-demo\work\branches)
error[E0308]: mismatched types
 --> src\main.rs:4:8
  |
4 |     if number {
  |        ^^^^^^ expected `bool`, found integer

For more information about this error, try `rustc --explain E0308`.
error: could not compile `branches` (bin "branches") due to 1 previous error
```

JavaScript treats 0, the empty string, `null`, `undefined` and a few others as false and the rest as true
(truthy and falsy). Rust has no such
rule, so you write an expression that is a `bool`, such as `number != 0`. The kind of bug where `if (count)` misses
the zero case cannot happen.

### if is an expression

`if` is an expression too, so it has a value. JavaScript's ternary `condition ? 5 : 6` looks like this in Rust:

Rust has no ternary operator; `if` already is a value, so it does not need one. Both branches must have the same

### loop can return a value

Rust has three loops: `loop`, `while` and `for`. `loop` repeats until a `break`. It is JavaScript's
`while (true)`, except that `break` can carry a value and make the whole loop a value. With the Book's example:

```rust title="src/main.rs"
fn main() {
    let mut counter = 0;

    let result = loop {
        counter += 1;

        if counter == 10 {
            break counter * 2;
        }
    };

    println!("The result is {result}");
}
```

### Loop labels

In nested loops, `break` and `continue` apply to the innermost one. To target an outer loop, give it a label such as
`'outer:`. JavaScript has labels too; the only difference is the leading `'`.

```rust title="src/main.rs"
fn main() {
    'outer: for i in 1..=3 {
        for j in 1..=3 {
            if j == 2 {
                continue 'outer;
            }
            if i == 3 {
                break 'outer;
            }
            println!("i = {i}, j = {j}");
        }
    }
    println!("done");
}
```

```console
❯ cargo run
   Compiling loops v0.1.0 (C:\Users\Jam\rust-demo\work\loops)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.31s
     Running `target\debug\loops.exe`
i = 1, j = 1
i = 2, j = 1
done
```

When `j` reaches 2, `continue 'outer` moves on to the next `i`, so only `j = 1` is printed. When `i` reaches 3,
`break 'outer` leaves both loops.

### while and for

`while` repeats while its condition is true, as in JavaScript. For walking through an array, though, `for` is
safer. Here both walk the same array, followed by a countdown over a reversed range (`1..4`):

```rust title="src/main.rs"
fn main() {
    let a = [10, 20, 30];

    let mut index = 0;
    while index < a.len() {
        println!("while: {}", a[index]);
        index += 1;
    }

    for element in a {
        println!("for: {element}");
    }

    for number in (1..4).rev() {
        println!("{number}!");
    }
    println!("LIFTOFF!!!");
}
```

```console
❯ cargo run
   Compiling loops v0.1.0 (C:\Users\Jam\rust-demo\work\loops)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.34s
     Running `target\debug\loops.exe`
while: 10
while: 20
while: 30
for: 10
for: 20
for: 30
3!
2!
1!
LIFTOFF!!!
```

Get the `index < a.len()` condition wrong in the `while` version and you hit the out-of-bounds panic from earlier.
`for element in a` is JavaScript's `for (const element of a)`, and since there is no index to manage, that risk
goes away. `1..4` is the range from 1 up to but not including 4, and `.rev()` reverses it. With `=`, as in `1..=3`,
the end is included (the label example used it).

## End-of-chapter exercise: Fibonacci numbers

Chapter 3 ends with three exercises: converting temperatures, generating the nth Fibonacci number, and printing the
lyrics of "The Twelve Days of Christmas". Here I solve the Fibonacci one, since it doubles as a real overflow
example.

```rust title="src/main.rs"
fn fib(n: u32) -> u32 {
    if n == 0 {
        return 0;
    }
    let mut prev = 0;
    let mut curr = 1;
    for _ in 1..n {
        let next = prev + curr;
        prev = curr;
        curr = next;
    }
    curr
}

fn main() {
    for n in [1, 2, 10, 47, 48] {
        println!("fib({n}) = {}", fib(n));
    }
}
```

It uses both an early `return 0;` and a final expression, `curr`. The `_` in `for _ in` names a value that is not
used. Run it:

```rust title="src/main.rs"
        let next = prev + curr;

        curr = next;

```

## Summary

- `let` cannot change and `let mut` can; the same word `let` means the opposite in TypeScript
- `const` requires a type and only takes values known at compile time
- Shadowing recreates a variable under the same name, and unlike `mut` it can change the type
- Integer types are split by size and sign. Overflow panics in debug and wraps in release; use `checked_add` and
  friends to make the intent explicit
- Integer division truncates toward zero, and integers and floats do not mix
- A `char` is 4 bytes, and a string's `len()` counts bytes
- An array's length is part of its type, and reading past the end panics
- `let` is a statement, while blocks and `if` are expressions. A final expression without `;` is the value; add the
  `;` and it becomes `()`
- `if` conditions must be `bool`, and `if` used as an expression replaces the ternary operator
- `loop` can return a value through `break`, labels target outer loops, and `for` is the way to walk an array

TypeScript at all, so expect a lot of errors.
