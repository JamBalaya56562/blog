## About this series

[The Rust Programming Language](https://doc.rust-lang.org/book/), known as "the Book", is Rust's official
introductory book. It is free to read on the Rust website, and each chapter has you write and run code.

This series works through the Book from the start, actually doing what it says. Rather than copying its text
and code, these posts show what happened when I ran the Book's code, and what happened when I changed it on
purpose. Rust's compiler errors are unusually helpful, so seeing "write this and it complains like that" is,
I think, the best way to learn. The Book is licensed under MIT or Apache-2.0, at your option
([COPYRIGHT in its repository](https://github.com/rust-lang/book/blob/main/COPYRIGHT)).

This first post covers chapters 1 and 2 of the Book:

- Chapter 1: install Rust, run Hello, World!, use Cargo
- Chapter 2: build a guessing game

The published Book's [title page](https://doc.rust-lang.org/book/title-page.html) assumes Rust 1.97.0 or later
with `edition = "2024"`. Everything here was tried with Rust 1.99.1 and mise 2026.10.11, in PowerShell on
Windows 11.

## Installing Rust with mise

The Book tells you to install Rust with [rustup](https://rustup.rs/), the official tool that installs Rust's
compiler and tools by version and switches between them. This blog manages its tools with
[mise](/en/blog/getting-started-with-mise), so Rust goes in through mise too.

mise does not keep Rust itself, though. According to [mise's docs](https://mise.jdx.dev/lang/rust.html), mise
installs Rust through rustup, installing rustup first if it is missing. Rust lands in rustup's homes (`~\.rustup`
and `~\.cargo` by default), and mise only keeps a link to them.

So as not to disturb my everyday setup, this recording pointed mise's and rustup's homes at a separate folder
(`C:\Users\Jam\rust-demo\home`) and started from nothing. Where the output shows those paths, a normal setup
would show `~\.cargo` and so on.

### mise use -g rust

`mise use -g rust` installs Rust globally. `-g` writes to the global configuration file, which applies in every
folder. Without a version, you get the latest stable release.


It downloaded `rustup-init` (12.7 MB) and installed Rust 1.99.1. The rustup lines are mixed in because mise is


### Windows needs a linker and Windows' libraries

The `x86_64-pc-windows-msvc` in `rustup toolchain list` is the name of a Rust *target*: "build for 64-bit
Windows, the way Microsoft's MSVC does". The Rust side of it is already in place after `mise use -g rust`.

What is missing lives outside Rust. The MSVC target borrows two things from Visual Studio: the linker, which joins
compiled pieces into an `.exe`, and Windows' standard libraries (the C runtime and the Windows SDK). The Book's
[installation section](https://doc.rust-lang.org/book/ch01-01-installation.html) also says to install Visual
Studio on Windows.

The machine used here already had Visual Studio's C++ build tools. `vswhere`, which comes with the Visual Studio
installer, shows that.

```console
❯ & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -products * -property displayName
Visual Studio Build Tools 2026
❯ & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools
```

The second command looks for a Visual Studio that includes the C++ tools (`VC.Tools.x86.x64`). If it prints
nothing, they are not installed.

#### The standard way: winget

mise's registry has no entry for Visual Studio's build tools. The standard way is the winget one-liner from
rustup's [docs](https://rust-lang.github.io/rustup/installation/windows-msvc.html).

```powershell
winget install --id Microsoft.VisualStudio.Community --source winget --force --override "--add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 --add Microsoft.VisualStudio.Component.VC.Tools.ARM64 --add Microsoft.VisualStudio.Component.Windows11SDK.22621 --addProductLang En-us"
```

It installs Visual Studio Community together with the C++ tools (x64 and ARM64), the Windows 11 SDK and the
English language pack. Community is free for individuals. According to rustup's docs, if you already have a
Visual Studio license you may replace `Community` with `BuildTools`. This machine already had the tools, so I
did not run this command.

#### Doing it with mise: xwin and rust-lld

There is also a way to get by with mise alone, without installing Visual Studio.
[xwin](https://github.com/Jake-Shadle/xwin) downloads just the MSVC C runtime and the Windows SDK libraries from
Microsoft and unpacks them into a folder. The linker is `rust-lld`, which ships with Rust. It is not an official
route, but in the recording environment it built and ran the guessing game.

xwin is not in mise's registry, but the `github:` form, which installs from a GitHub release, works.

```console
❯ mise use -g github:Jake-Shadle/xwin
...

```

read it before adding the flag. `--disable-symlinks` skips the symbolic links xwin would add to paper over
upper/lower-case differences: Windows file systems are case-insensitive, so they are not needed, and creating
symbolic links on Windows can require extra privileges.


#### Crates containing C code

Every crate the guessing game uses is pure Rust. Some crates, though, contain C code and call a C compiler while
building. xwin only provides libraries and headers; it has no C compiler.

To check this, I made a small crate, `cdemo`, that calls one C function. `build.rs` is a script Cargo runs before
building; here it uses the [cc](https://crates.io/crates/cc) crate to compile `greet.c`.

```c title="src/greet.c"
#include <string.h>

int c_len(const char *text) {
    return (int)strlen(text);
}
```

```rust title="build.rs"
fn main() {
    cc::Build::new().file("src/greet.c").compile("greet");
}
```

```rust title="src/main.rs"
use std::ffi::{c_char, c_int};

unsafe extern "C" {
    fn c_len(text: *const c_char) -> c_int;
}

fn main() {
    let len = unsafe { c_len(c"Hello from C".as_ptr()) };
    println!("C says the text is {len} bytes long");
}
```

`unsafe` and `extern "C"` are how Rust calls C functions, covered in the Book's chapter 20; the details do not
matter here.

On the same runner, with only the xwin configuration, this crate failed to build because no C compiler was found.

```text
  error occurred in cc-rs: failed to find tool "cl.exe": program not found
```

The C compiler can come from mise too. The `clang` in mise's registry (`conda:clang`, which installs the
[conda-forge](https://conda-forge.org/) package) includes `clang-cl`, which compiles the MSVC way. For bundling the
compiled C into a static library, `llvm-ar` from Rust's `llvm-tools` component does the job.

```powershell
mise use -g conda:clang
rustup component add llvm-tools
```

Environment variables tell the cc crate which compiler to use and where the headers are. `/imsvc` is the clang-cl
option that reads the folders xwin unpacked as system headers.

```powershell

$env:AR_x86_64_pc_windows_msvc = (Get-ChildItem -Recurse -Filter llvm-ar.exe (rustc --print sysroot)).FullName | Select-Object -First 1
$env:CFLAGS_x86_64_pc_windows_msvc = "/imsvc $x/crt/include /imsvc $x/sdk/include/ucrt /imsvc $x/sdk/include/um /imsvc $x/sdk/include/shared"
```

On the runner, that built and ran the crate that calls C as well (xwin's folder there is `D:/a/_temp/xwin`).


#### Which to choose

xwin's README describes it as a tool for compiling and linking Windows programs from a non-Windows platform, so
using it on Windows is off its intended path. It worked for everything tried here, but larger crates and crates
with C++ were not tried. When in doubt, installing Visual Studio with winget is the dependable choice; reach for
xwin when you want everything from mise or would rather not install Visual Studio.

## Hello, World! (section 1.2)

First, without Cargo, using the compiler `rustc` directly. In a folder called `hello_world`, write `main.rs`.

```rust title="main.rs"
fn main() {
    println!("Hello, world!");
}
```

`fn main()` is the function the program starts from. `rustc main.rs` compiles it.

```console
❯ rustc main.rs
❯ Get-ChildItem -Name
main.exe
main.pdb
main.rs
❯ .\main.exe
Hello, world!
```

It finished without printing anything and left `main.exe` and `main.pdb` behind. `main.exe` is the executable
and `main.pdb` holds debugging information. Unlike JavaScript or Python, Rust compiles to an executable first and
then runs that.

```console
❯ Get-ChildItem main.exe, main.pdb | Select-Object Name, Length | Format-Table -AutoSize

Name      Length
----      ------
main.exe  134144
main.pdb 1306624
```

The executable is about 131 KB.

### Functions and macros

The `!` at the end of `println!` marks it as a **macro**, not a function. JavaScript and Python have no macros,
so a short explanation is in order.

A **function** takes a fixed number of arguments of fixed types and is called while the program runs.
`fn main()` is a function.

A **macro** rewrites the code you wrote into other code before compilation. The Book's
[macros section](https://doc.rust-lang.org/book/ch20-05-macros.html) calls it "writing code that writes other
code". At compile time, `println!("Hello, world!")` expands into longer code that formats the text and writes it
out. The compiler does the expanding, so you normally never see the expanded code.

The difference shows most clearly in the number of arguments. A Rust function takes a fixed number of them. Here
`greet` takes one argument and is given two.

```rust title="fn_args.rs"
fn greet(name: &str) {
    println!("Hello, {name}!");
}

fn main() {
    greet("Rust");
    greet("Rust", 11);
}
```

```console
❯ rustc fn_args.rs
error[E0061]: this function takes 1 argument but 2 arguments were supplied
 --> fn_args.rs:7:5
  |
7 |     greet("Rust", 11);
  |     ^^^^^         -- unexpected argument #2 of type `{integer}`
  |
note: function defined here
 --> fn_args.rs:1:4
  |
1 | fn greet(name: &str) {
  |    ^^^^^
help: remove the extra argument
  |
7 -     greet("Rust", 11);
7 +     greet("Rust");
  |

error: aborting due to 1 previous error

For more information about this error, try `rustc --explain E0061`.
```

"This function takes 1 argument but 2 were supplied." Rust has no optional parameters like TypeScript's
`name?: string`, and no variable-length parameters like JavaScript's `...args`.

`println!`, on the other hand, takes any number of arguments.

```rust title="varargs.rs"
fn main() {
    let name = "Rust";
    let age = 11;
    println!("Hello!");
    println!("Hello, {name}!");
    println!("Hello, {}! You are {} years old.", name, age);
}
```

```console
❯ rustc varargs.rs
❯ .\varargs.exe
Hello!
Hello, Rust!
Hello, Rust! You are 11 years old.
```

One argument or three, it works. As the second line shows, a variable's name can even go straight inside the
string as `{name}`. A macro reads the code you wrote before it is compiled, which is what makes that possible.

The other benefit is that mistakes surface at compile time. What if there are two `{}` but only one argument?

```console
❯ Get-Content too_few.rs
fn main() {
    let name = "Rust";
    println!("Hello, {}! You are {} years old.", name);
}
❯ rustc too_few.rs
error: 2 positional arguments in format string, but there is 1 argument
 --> too_few.rs:3:22
  |
3 |     println!("Hello, {}! You are {} years old.", name);
  |                      ^^          ^^              ----

error: aborting due to 1 previous error
```

It stopped before the program ever ran: "two `{}` in the string, but one argument". While expanding, `println!`
reads the format string and matches its `{}` against the arguments. With an ordinary function the compiler cannot
see inside the string, so it could not do this.

Macros come up again and again in this series, and the Book's chapter 20 covers writing your own. For now it is
enough to know that a name ending in `!` is a macro, and that it expands into code before compilation.

### Taking out the `!` in `println`

To see what happens without the `!`, `no_bang.rs` changes it to `println(`.

```console
❯ Get-Content no_bang.rs
fn main() {
    println("Hello, world!");
}
❯ rustc no_bang.rs
error[E0423]: cannot find function `println` in this scope
 --> no_bang.rs:2:5
  |
2 |     println("Hello, world!");
  |     ^^^^^^^ not found in this scope
  |
  = note: a macro named `println` exists in another namespace
help: use `!` to invoke the macro
  |
2 |     println!("Hello, world!");
  |            +

error: aborting due to 1 previous error

For more information about this error, try `rustc --explain E0423`.
```

"There is no function called `println`, but there is a macro by that name; add `!` to call it." It even shows
the fix: the `+` line marks where the character goes. Errors carry codes like `E0423`, and
`rustc --explain E0423` prints a longer explanation.

### Taking out the trailing `;`

Next, `no_semi.rs` drops the `;` at the end of the line.

```console
❯ Get-Content no_semi.rs
fn main() {
    println!("Hello, world!")
}
❯ rustc no_semi.rs
❯ .\no_semi.exe
Hello, world!
```

No error this time. In Rust the last expression in a block may go without `;`, and its value becomes the
block's value. `println!` returns the "nothing" value `()`, which is also what `main` returns, so it is fine.
Chapter 3 covers this properly, and the next post comes back to it.

## Hello, Cargo! (section 1.3)

Real Rust projects rarely call `rustc` directly; they use **Cargo**. Cargo builds, runs, tests and manages the
packages a project depends on (in Rust, "crates"). In JavaScript terms it is npm and a build tool in one.

`cargo new` creates a project.

```console
❯ cargo new hello_cargo
    Creating binary (application) `hello_cargo` package
note: see more `Cargo.toml` keys and their definitions at https://doc.rust-lang.org/cargo/reference/manifest.html
❯ cd hello_cargo
❯ Get-ChildItem -Force -Name
.git
src
.gitignore
Cargo.toml
```

The source goes under `src`, and a Git repository (`.git`) and `.gitignore` came with it. `.gitignore` lists
only `/target`, where build output goes.

```console
❯ Get-Content Cargo.toml
[package]
name = "hello_cargo"
version = "0.1.0"
```

### Cargo calls rustc for you

`rustc` is the Rust compiler itself: it takes `.rs` files and produces executables and libraries. Cargo is not a
compiler. It decides which files to compile, in what order and with which settings, and then calls `rustc`. In
TypeScript terms, `rustc` is `tsc`, and Cargo is npm plus the scripts that call `tsc`.

`cargo build -v` shows the commands Cargo actually runs.


## Building the guessing game (chapter 2)

Chapter 2 builds a game where you guess a secret number between 1 and 100. The Book adds code a little at a
time and touches most of Rust's basics on the way. This post follows the same order.

```console
❯ cargo new guessing_game

```

The game reads numbers from standard input, so here they are piped in from PowerShell. That is why the input
values themselves do not appear on screen.

### Reading input

The first version reads one line and prints it back.

```rust title="src/main.rs"
use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}
```

```console
❯ "42" | cargo run
   Compiling guessing_game v0.1.0 (C:\Users\Jam\rust-demo\work\guessing_game)

     Running `target\debug\guessing_game.exe`

Please input your guess.

```

The empty line at the end is there because `read_line` keeps the line's trailing newline in `guess`. That
matters later.

Three very Rust things are packed in here:

- `let mut guess`: Rust variables are **immutable by default**; only `mut` makes them changeable
- `&mut guess`: `guess` is passed to `read_line` as a reference it may modify. `&` makes a reference, which leads
  into chapter 4's ownership
- `.expect(...)`: `read_line` returns a `Result`, which says whether it succeeded. `expect` stops the program
  with its message if it failed

### Turning the string into a number

The fix is to convert the input before comparing. The Book does it by creating a new variable with the same
name, `guess`.

```rust title="src/main.rs"
    let guess: u32 = guess.trim().parse().expect("Please type a number!");
```

Declaring a variable with the same name again hides the earlier one. This is called **shadowing**, and it saves
inventing names like `guess_str` and `guess_num`. `trim()` removes surrounding whitespace and the newline,
`parse()` converts to a number, and `u32` is an unsigned 32-bit integer.

### Looping, and shrugging off non-numbers

![trim removes whitespace from the input string, then parse converts it to u32. Successful values are compared; failed conversions continue to the next input](/rust/guess-input.avif)

Finally, let the player guess until they get it. The Book's final version wraps everything in `loop` and leaves
with `break` on a correct guess. So that non-numbers no longer stop the program, a `match` on the result of
`parse()` replaces `expect`. The secret number is no longer printed. This is the same code as the Book's
listing 2-6.

```rust title="src/main.rs"
use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    loop {
        println!("Please input your guess.");

        let mut guess = String::new();

        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let guess: u32 = match guess.trim().parse() {
            Ok(num) => num,
            Err(_) => continue,
        };

        println!("You guessed: {guess}");

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Too small!"),
            Ordering::Greater => println!("Too big!"),
            Ordering::Equal => {
                println!("You win!");
                break;
            }
        }
    }
}
```

`parse()` returns a `Result`: `Ok(number)` on success, `Err(error)` on failure. `Ok(num) => num` takes the
number out, and `Err(_) => continue` goes back to the top of the loop on failure. `_` means "I do not need the
value".

## A trap I hit: the game never stops when input runs out

Piping input in turned up one problem. If the input runs out before a correct guess, the program never stops.
Here only `50` goes in, and only the first 8 lines are kept.

```console
❯ "50" | cargo run -q | Select-Object -First 8
Guess the number!
Please input your guess.
You guessed: 50
Too small!
Please input your guess.
Please input your guess.
Please input your guess.
Please input your guess.
```

Without `Select-Object -First 8` to cut it off, `Please input your guess.` keeps coming forever. Once input is
exhausted, `read_line` does not fail; it succeeds having read 0 bytes. `guess` stays empty, `parse()` fails,
`continue` loops back, `read_line` reads 0 bytes again, and so on. Playing from the keyboard normally avoids
this. Feeding input in a test hits the same thing, and ending input with `Ctrl+Z` and Enter on Windows should
hit it too, by the same logic (I did not try that case).

Checking the byte count `read_line` returns and leaving the loop on 0 fixes it. To keep to the Book's flow,
this post leaves it as is.

## Summary

- Installing Rust through mise still runs rustup underneath; mise passes the version on through
  `RUSTUP_TOOLCHAIN`
- On Windows, the linker and Windows' libraries come from Visual Studio's C++ build tools, normally installed
  with winget. Using only tools from mise, xwin and `rust-lld` built and ran the game on a Windows runner with
  Visual Studio removed, and `conda:clang`'s clang-cl handled a crate with C code
- `rustc` on its own compiles to an executable (`.exe`); day to day, Cargo's `build`, `run` and `check` do the work
- `Cargo.toml` is `package.json` and `Cargo.lock` is `package-lock.json`; `"0.10.1"` means "at least 0.10.1,
  below 0.11.0"
- Variables are immutable by default, an ignored `Result` draws a warning, trait methods need a `use`, and
  values of different types cannot be compared
- Compiler errors say not only what is wrong but how to fix it; breaking code and reading them is the best
  teacher
